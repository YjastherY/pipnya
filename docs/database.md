# Проектирование и обслуживание БД

## Предметная область

Пользователь публикует короткую заметку. У заметки один автор и до трёх тегов. Пользователи подписываются друг на друга и могут сохранять чужие или свои заметки. Удаление записи должно удалять связанные теги и закладки; удаление учётной записи не должно оставлять записей без автора.

## Нормализация

`users`, `posts` и `tags` хранят независимые сущности. Связи многие ко многим вынесены в `post_tags`, `follows` и `bookmarks` с составными первичными ключами. Имя тега хранится один раз, а не повторяется текстом в каждой записи. Такая схема не допускает дубликатов подписок, закладок и связей записи с тегом. Все неключевые поля зависят от ключа своей таблицы; схема соответствует третьей нормальной форме для текущей предметной области.

## Ограничения и индексы

Полный DDL находится в [app/schema.sql](../app/schema.sql). Внешние ключи включаются для каждого соединения (`PRAGMA foreign_keys = ON`). Таблицы используют `UNIQUE`, `CHECK` и `ON DELETE CASCADE`. Индекс по дате ускоряет ленту; индексы по автору, тегу, подписке и закладке ускоряют соответствующие выборки. Поиск по тексту использует `LIKE` с экранированием спецсимволов; для крупной базы следующий шаг — FTS5.

## SQL-операции

Примеры запросов приложения:

```sql
SELECT p.id, p.body, u.username
FROM posts p
JOIN users u ON u.id = p.author_id
ORDER BY p.created_at DESC, p.id DESC
LIMIT 10;

SELECT p.id, p.body
FROM posts p
WHERE EXISTS (
    SELECT 1 FROM follows f
    WHERE f.followed_id = p.author_id AND f.follower_id = ?
);
```

Запись публикации и обновление её тегов выполняются в одной транзакции. Пользовательские значения передаются параметрами `?`, а не вставляются в SQL-строку.

## Администрирование

```bash
flask --app run.py check-db
flask --app run.py backup-db backups/microblog.sqlite3
```

`check-db` выполняет `PRAGMA integrity_check` и `PRAGMA foreign_key_check`. `backup-db` использует SQLite Backup API для согласованной копии открытой базы. Файлы базы, резервные копии и `.env` исключены из Git. На сервере каталог базы должен быть доступен только процессу приложения и располагаться на постоянном диске.

## Защита данных

Пароли хешируются средствами Werkzeug. Веб-приложение не отдаёт файл БД через статический маршрут. Flask подписывает cookie сессии секретом из окружения; в продакшене обязательны `SECRET_KEY` и HTTPS. У cookie включены `HttpOnly`, `SameSite=Lax` и, в продакшене, `Secure`. Изменяющие API-запросы требуют CSRF-токен. Сервер проверяет владельца записи до изменения или удаления. Ограничения длины и размера запроса уменьшают риск некорректных данных и перегрузки.
